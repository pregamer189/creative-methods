# Running the work

How work moves from day to day so it stays sharp, cheap and in the owner's
direction. Collected from what worked and from every correction the owner made.

## Chunks

- **One chunk per thread or session, with a finish line.** It ends with a handoff
  file (what was done, where things live, what's next) and one line in a sessions
  log. Hand off at a safe point before context runs out.
- **Three or four lanes at most** at once. More lanes means nobody finishes.
- **Bigger pushes, not tiny questions** (Elias, 2026-11-01). Keep planning and
  building the small parts until a part is complete; don't stop for a detail.
- **Short, batched output.** The owner skims; one message per result.

## The plan and the critic pass

Before building anything non-trivial, write a plan of 5-10 numbered lines:

1. What the person gains.
2. What it rests on (earlier decisions, marks, research), each named.
3. The change.
4. The batch: exactly what gets made this round.
5. What is left out, on purpose.
6. Rules kept (the hard rules that apply).
7. How it is shown for review.
8. How it is judged.

Then a **critic pass** on the plan, written down, with at least these questions:

- **Would this fit any other product?** If yes, what makes it ours? Keep that part.
- **Which past miss could this repeat?** Name it and the guard against it.
- **Is it kid-like, busy, cheap-looking or generic?** Name the risk and the fix.
- **Does it add a tap or a wait to the core task?**

A fresh reviewer that sees only the references and the plan, not the reasoning,
does the critic pass for anything big. Checks by the same model share its blind
spots (Elias, I14).

## Decide and log

Elias, 2026-11-01: "you stop for my choice way too much... do more research
instead of asking all the time." So:

- Anything research, references or a critic pass can settle is decided, not asked.
- Every decision goes into a numbered decisions log: **the decision, the evidence,
  and what the owner can still veto by marking the built piece.**
- The owner is shown only finished, polished pieces, in occasional batches, to mark
  what they dislike. A dislike means rework from research, not a new pick page.
- Only true taste questions go to the owner, batched.
- Never dismiss an idea by citing an earlier decision; decisions are context, not
  walls.

## Hard rules from repeated misses

- One miss is a note. **Two misses on the same thing** (a look rejected twice, the
  same wording problem twice) start real research on that area and end in a
  **hard rule** written where every later piece is checked against it.
- Hard rules carry the owner's words, a date and the reason.
- Every rule lives in one home; other files link to it.

## Feedback

- **Read the feedback first.** Before planning an area, read every earlier mark
  and comment on it. The plan says which feedback it answers.
- **Every comment gets a visible change or a direct answer.** List each one back
  with what was done.
- **Keep a preferences log.** Each round, copy every mark, tag and comment into one
  file (newest round first), then clear the review page. At the top, keep a short
  list of **what the marks keep saying** (for us: "cheap" goes with synthetic sounds,
  stock effects, grey surfaces and bare layouts). That list is how the process gets
  tuned.
- **Quote, don't paraphrase.** Voice briefs are saved verbatim, then turned into a
  numbered nuance table (each nuance, and where it lives in the build). Nothing is
  called "your idea" without the quote and a link.
- **Snapshot the method.** When a method changes in a big way, save a dated copy of
  it, so you can see what changed results.

## Spending

- **Know what each paid generation is for before making it** (a voice clip, a sound,
  an image). No exploratory batches. Set a hard cap per project and log the spend.
- **Cache everything that is generated**, one canonical checked copy per key, reused
  for everyone. Make each asset the first time something real needs it.
- **Measure the real cost.** Estimates from tools can be far off (we saw one about 3x
  too high); log what was really charged.
- **Cheap first:** plans, sketches and prototypes before builds. High effort for
  research and planning; low effort only for lookups with a known answer.
- **Plans are the cache:** read the plans before the sources; never re-research what
  a brief already answers.

## Safety

- Ask before every change or delete on the owner's own computer; reading is fine.
- Nothing irreversible (sending outside, deleting, paying) without the owner's yes.

## Only what was asked

- Add nothing to finished work that the owner did not ask for (an effect, a
  colour blend, an extra element). Suggest it in one sentence instead.
- If something was added anyway, list every such addition so it can be removed in
  one pass.
